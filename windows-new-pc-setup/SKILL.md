# Windows 新电脑安装与配置

按用户笔记完成安装与设置，保留可恢复配置和实际核验记录。先确定笔记路径，再阅读 [执行顺序与注意事项](references/workflow.md)，按当前阶段直接读取该路径下的源文档。

## 范围与输入

- 用户指定的阶段、排除项和新偏好优先。默认完成非可选、非手动的安装与配置；“手动安装”整节列为用户清单，用户明确要求自动处理其中某项时再执行。可选软件、使用示例、故障处理命令不会自动执行。
- 先盘点现有安装、配置、代理和目录；已满足的项目核验后跳过，已有配置按项合并。不要将整份文档当作脚本批量执行。
- 以下是这位用户的默认偏好，不是对任意电脑的事实：Git 用户名与邮箱从目标机已有配置读取；未配置时请用户提供，不内置个人身份；本地 HTTP/SOCKS 代理端口 `1130`；项目目录 `D:\project\self`；游戏助手目录 `E:\miHoYo\maa`。已有不同配置先保留并说明；缺少对应磁盘、代理协议不符或身份归属不明确时只询问依赖该信息的部分。
- 用户目录、Documents、Startup、Scoop 根目录、PowerShell profile、Terminal 实际配置位置必须在目标机发现。不要照抄旧机的 `C:\Users\YOUR_USERNAME` 或 `D:\Documents`。
- 笔记中的个人身份和旧机路径不能直接套用。`YOUR_USERNAME` 必须替换为目标机实际用户名，Git 用户名与邮箱由用户提供；不要直接执行包含占位符的配置或注册表文件。
- 用户指定路径下的当前笔记是安装清单、版本和配置偏好的依据；与本技能中的历史示例冲突时，以用户当前要求和笔记为准。软件包名或配置格式变化时查官方资料或已安装版本。

## 笔记路径

- 使用用户在当前任务或同一会话中明确指定的笔记根目录，记为 `NOTE_ROOT`。未提供路径时先询问，不猜测固定目录。
- 执行安装前确认路径存在且可读，将相对路径解析为绝对路径。路径不可访问时说明原因，请用户提供有效路径；不回退到技能内副本或历史快照。
- 下列文档路径均相对于 `NOTE_ROOT`，不相对于技能目录。每个阶段开始时直接读取原位置的当前文件，不将笔记复制到技能的 `references/` 下。
- 文档相对链接和资源路径按引用它们的笔记所在目录解析。目录结构变化时先在 `NOTE_ROOT` 内查找；存在多个候选或无法定位时，仅询问受影响部分。
- `references/workflow.md` 仅提供执行注意事项，不能代替笔记原文。保留笔记源文件；需要适配目标机的配置资源，在安装目标位置或临时副本中修改。

## 按阶段执行

1. **准备与网络**：读取 `系统/win/software/优先事项.md` 的“开始”和“设置项”。盘点机器、网络与用户手动前置事项，确认包管理器可用。
2. **基础环境**：读取 `系统/win/software/scoop.md`、`系统/general tools/git/config&problem.md`、`系统/win/software/powershell.md`、`系统/win/software/win_terminal.md`，按依赖顺序安装及配置。
3. **常用软件**：按优先事项“软件安装”的 winget、uwp、官网、GitHub、scoop 分类安装，完成每项附带设置。Typora 必须读取 `系统/general tools/typora.md`。软件安装和配置分别记录，不能以安装成功代替设置完成。
4. **开发环境**：读取 Scoop 的“开发工具安装”和“具体语言配置”；安装工具后依次设置 Java、Python/Conda、JS/TS、Go、Android。可选 PHP 和项目示例默认排除。
5. **扩展环境及用户选择的项目**：若用户要求整个开发工具安装，语言配置后继续 Scoop 文档的 AI CLI，再最后处理 Docker/WSL；仅要求具体语言配置时不包括这些。Docker 相关配置见 `系统/general tools/docker_desktop/docker_env_win.md`。四个游戏助手便携包、手动清单和可选软件依用户选择处理；不要把历史一次性授权当作新机器上的默认范围。
6. **核验与交接**：在新终端环境检查命令实际路径、版本、代理和配置加载，完成必要的小型运行检查；汇总已完成、未验证、用户操作与阻塞项。

阶段之间可继续独立任务，不因账号登录或单个界面设置阻塞其他软件。只在有新依据时重试失败步骤，连续两次同类失败后换有依据的方法或记录阻塞，避免反复安装和重复询问。

## 资源与记录

- 从 `NOTE_ROOT` 直接读取资源：软件资源在 `系统/win/software/resources/`，Git 启动配置在 `系统/general tools/git/resources/`。复制前读取内容，将旧机绝对路径替换成目标机实际路径。
- 在 `NOTE_ROOT` 的 `核对记录/` 写入当次日期的核对记录。若笔记目录不可写，记录写到用户选择的工作目录，并在最终回复提供绝对路径。
- 记录至少包含项目、安装渠道/版本、配置改动、验证依据、备份位置、未完成原因。不要记录账号令牌、私钥或许可证密钥。
- 完成后告知哪些改动需新开终端、重启软件或手动操作。没有实际验证的 UI 效果要明确标注。

## 迁移与调用

将整个 `windows-new-pc-setup` 文件夹复制到新电脑的 `$CODEX_HOME/skills/`（未设置时为 `~/.codex/skills/`），让客户端重新加载技能后调用：

> 使用 $windows-new-pc-setup，笔记根目录为 `<我的笔记绝对路径>`，配置这台新电脑，排除手动安装和可选项，先完成基础环境，再安装软件及开发语言。

也可只请求某一阶段或“按核对记录继续”。本技能不保存旧机的“完成”状态，新机器必须重新盘点。
